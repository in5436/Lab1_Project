# Схема підключення та Pinout-таблиця: Server Rack Health Monitor

Документ визначає фізичне та логічне підключення всіх компонентів сенсорної підсистеми **Server Rack Health Monitor** до плати **NUCLEO-C031C6**. Кожне інженерне рішення обґрунтоване посиланням на первинну документацію STMicroelectronics та виробників сенсорів:

1. **Рівень кристала МК:** *DS13867 Rev 4* — STM32C031x4/x6 Datasheet (таблиці призначення виводів та альтернативних функцій AF).
2. **Рівень периферії МК:** *RM0490 Rev 3* — STM32C0x1 Reference Manual (дерево тактування RCC, розрахунок регістрів `I2C_TIMINGR`, `USART_BRR`, часові параметри `ADC1`).
3. **Рівень плати розширення:** *UM2953 Rev 2* — STM32C0 Nucleo-64 boards User Manual (розкладка роз'ємів Arduino Uno V3 та ST morpho, бортові компоненти, бюджет регулятора живлення).
4. **Рівень сенсорів:** *MPU-6000/6050 Product Specification Rev 3.4* та *Register Map Rev 4.2*, *TI LM35 Datasheet (SNIS159H)*, *Omron SS Limit Switch Datasheet*.

## 3. Бюджет живлення системи

У симуляторі Wokwi всі компоненти стенда живляться від шини **`3V3`** плати **NUCLEO-C031C6**. Потенціометр `temp1` емулює аналоговий вихід LM35, проте реальний датчик LM35 потребує живлення від 4 до 30 В згідно з документацією Texas Instruments. Для фізичної реалізації передбачається живлення LM35 від лінії `5V` плати Nucleo зі спільною землею (`GND`), при цьому вихід `Vout` підключається до входу `PA0` (`ADC1_IN0`). Згідно з *UM2953 Rev 2, §6.5.2 (с. 14)*, максимальний сумарний струм лінії `3V3` та USB-живлення плати обмежений значенням **500 мА** (бортовий LDO-стабілізатор `LD39050PU33R` забезпечує до 500 мА).

| :--- | :--- | :--- | :--- | :--- |

**Висновок щодо живлення:** У симуляції Wokwi всі компоненти живляться від лінії `3V3` плати Nucleo. Для фізичної реалізації реальний LM35 повинен живитися від лінії `5V`, тоді як його вихідний аналоговий сигнал надходить на `PA0` (`ADC1_IN0`). При цьому напруга на вході ADC не повинна перевищувати допустимий діапазон мікроконтролера, а земля датчика має бути спільною із землею Nucleo. Окреме зовнішнє силове джерело живлення не потрібне, оскільки у складі системи відсутні силові виконавчі механізми.

## 4. Параметри шин та розрахунок таймінгів із дерева тактування

Згідно з конфігурацією `SystemClock_Config()` у `main.c` та `firmware.ioc`, система тактується від високошвидкісного джерела **HSE = 48 МГц** (`HSE_VALUE = 48000000U`) без додаткового ділення:
* **`SYSCLK` = 48 МГц** (`RCC_SYSCLK_DIV1`)
* **`HCLK` (шина AHB) = 48 МГц** (`RCC_HCLK_DIV1`)
* **`PCLK1` (шина APB) = 48 МГц** (`RCC_APB1_DIV1`)

### 4.1. Шина `I2C1` (Standard Mode, 100 кГц)
* **Тактування:** `f_I2CCLK = PCLK1 = 48 МГц` ($t_{\text{I2CCLK}} = \frac{1}{48\text{ МГц}} = 20.833\text{ нс}$).
* **Значення регістра `hi2c1.Init.Timing` (`I2C_TIMINGR`), згенероване у проєкті:** `0x10805D88` (*RM0490, §25.4.9*).
  * `PRESC` (біти 31:28) = `1` $\Rightarrow t_{\text{PRESC}} = (\text{PRESC} + 1) \times t_{\text{I2CCLK}} = 2 \times 20.833\text{ нс} = \mathbf{41.667\text{ нс}}$ (частота прескейлера 24 МГц).
  * `SCLDEL` (біти 23:20) = `8` $\Rightarrow t_{\text{SU;DAT}} = (8 + 1) \times 41.667\text{ нс} = 375.0\text{ нс}$.
  * `SDADEL` (біти 19:16) = `0`.
  * `SCLH` (біти 15:8) = `0x5D` (`93`) $\Rightarrow t_{\text{SCLH}} = (93 + 1) \times 41.667\text{ нс} = \mathbf{3.917\text{ мкс}}$.
  * `SCLL` (біти 7:0) = `0x88` (`136`) $\Rightarrow t_{\text{SCLL}} = (136 + 1) \times 41.667\text{ нс} = \mathbf{5.708\text{ мкс}}$.
* **Розрахунковий період `SCL`:** сума програмованих фаз $t_{\text{SCLH}} + t_{\text{SCLL}} = 3.917 + 5.708 = 9.625\text{ мкс}$. Із урахуванням часу синхронізації аналогового фільтра та фронтів ($t_{\text{SYNC1}} + t_{\text{SYNC2}} \approx 0.375\text{ мкс}$):
  $$T_{\text{SCL}} = 9.625 + 0.375 = \mathbf{10.00\text{ мкс}} \implies f_{\text{SCL}} = \frac{1}{10.00\text{ мкс}} = \mathbf{100.0\text{ кГц}}.$$

### 4.2. Інтерфейс `USART2` (115200 бод, 8N1)
* **Тактування:** `f_CK = PCLK1 = 48 МГц`, режим `Oversampling = 16`.
* **Розрахунок дільника `USARTDIV` (`USART_BRR`):**
  $$\text{USARTDIV} = \frac{48\,000\,000}{115\,200} = 416.667 \implies \text{BRR} = \mathbf{417}\text{ (`0x01A1`)}.$$
* **Фактична швидкість і тривалість біта:**
  $$\text{Baud}_{\text{actual}} = \frac{48\,000\,000}{417} = \mathbf{115\,107.91\text{ біт/с}}\quad(\text{похибка } -0.08\%, \text{що значно менше допустимих } \pm 2\%).$$
  $$T_{\text{bit}} = \frac{1}{115\,107.91} \approx \mathbf{8.687\text{ мкс}},\quad T_{\text{frame (10 bit)}} \approx \mathbf{86.87\text{ мкс}}.$$

### 4.3. Модуль `ADC1` (Канал `IN0`, 12 біт)
* **Тактування:** `ADC_CLOCK_SYNC_PCLK_DIV2` $\Rightarrow f_{\text{ADC}} = \frac{48\text{ МГц}}{2} = \mathbf{24\text{ МГц}}$ ($T_{\text{ADC\\_CLK}} = 41.67\text{ нс}$).
* **Час вибірки та перетворення:** `SamplingTimeCommon1 = ADC_SAMPLETIME_1CYCLE_5` (`1.5 циклу`), час квантування 12-бітного SAR-ядра = `12.5 циклів`:
  $$T_{\text{conv}} = \frac{1.5 + 12.5}{24\text{ МГц}} = \frac{14}{24\text{ МГц}} \approx \mathbf{0.583\text{ мкс}}.$$
* Імпульс на маркерному піні `PA4` (`ADC_CONV_MARK`) охоплює повний цикл викликів `HAL_ADC_Start()`, `HAL_ADC_PollForConversion()`, `HAL_ADC_GetValue()` та `HAL_ADC_Stop()`, тому його фактична тривалість на записі логічного аналізатора визначається часом виконання функцій HAL (близько кількох десятків мікросекунд).

## 6. Відхилені варіанти розкладки (Альтернативи)

Під час проектування схеми було розглянуто та відхилено три альтернативні варіанти призначення виводів.

### 1. Відхилений варіант А: Підключення кінцевого вимикача дверцят до PA3 або PA5

- **Причина відмови (конфлікт із бортовою обв'язкою Nucleo):** За документацією UM2953 (§6.6, §6.8) вивід `PA3` через перемичку `SB14` з'єднаний із виходом передавача ST-LINK VCP (`USART2_RX`), а до виводу `PA5` підключений бортовий світлодіод `LD4`. Використання будь-якого з цих пінів під кнопку унеможливило б прийом CLI-команд або світлову індикацію за `FR-07`.

### 2. Відхилений варіант Б: Підключення ліній MPU-6050 за записом із чорнової таблиці ЛР1 (SCL = PA10, SDA = PA9)

- **Причина відмови (невідповідність апаратній матриці альтернативних функцій кристала):** Перевірка за первинним документом DS13867 Rev 4 (Table 13, с. 34) показала, що на альтернативній функції `AF6` блок `I2C1` має жорстке закріплення: `PA9` може бути виключно `I2C1_SCL`, а `PA10` — виключно `I2C1_SDA`. Помилку в документації ЛР1 виправлено.

### 3. Відхилений варіант В: Використання пінів PA13 або PA14 під службовий маркер логічного аналізатора ADC_CONV_MARK

- **Причина відмови (конфлікт з інтерфейсом налагодження SWD):** Виводи `PA13` (`SWDIO`) та `PA14` (`SWCLK`) за замовчуванням перебувають у режимі `AF0` для зв'язку з програматором ST-LINK (UM2953, §6.7). Переназначення їх на `GPIO_Output` блокує можливість перепрошивання та налагодження МК на реальному обладнанні без апаратного скидання `NRST`. Тому під маркер АЦП обрано вільний пін `PA4` (`CN8.3`).
