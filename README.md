# Server Rack Health Monitor

Навчальний проєкт студента Лазінька Романа, група ІО-36, з курсу «Системне програмування вбудованих систем».

**Ідея:** система моніторингу фізичного стану серверної стійки. Вона відстежує удари та вібрації корпусу, підвищення температури й відкриття дверцят, а результати передає через UART.

У **ЛР3** досліджено роботу bare-metal прошивки на **STM32C031C6** зі **STM32 HAL**. Додано вимірювання часу виконання задач, періодів, джитера, затримки реакції та використання пам'яті. Проведено навантажувальні випробування, визначено обмеження super loop і підготовлено базову лінію для порівняння з FreeRTOS у ЛР4.

## Компоненти та робота системи

- **MPU-6050**: акселерометр через I²C1 (PA9/PA10, адреса `0x68`, 100 кГц). Використовується для виявлення ударів; номінальний період опитування 20 мс.
- **LM35**: аналоговий датчик температури через ADC1_IN0 (PA0). У Wokwi моделюється потенціометром `temp1`; поріг перегріву 45°C.
- **Кінцевий вимикач дверцят**: цифровий вхід PA1 з програмним debounce 50 мс.

У режимі `ACTIVE` система формує тривоги `SHOCK DETECTED`, `HIGH TEMPERATURE` та `DOOR OPENED`. У режимі `MAINTENANCE` опитування й телеметрія продовжуються, але звичайні тривоги не формуються. Повторні тривоги одного джерела обмежені інтервалом 5 с.

## Архітектура super loop

Прошивка побудована на шарах `Core`, `Platform`, `Devices` та `App`. Після ініціалізації й самоперевірки головний цикл безперервно викликає `Platform_Step()`, де послідовно виконуються приймання UART-команд, опитування датчиків, перевірка тривог, керування LED та передавання телеметрії.

Планування реалізовано через `HAL_GetTick()` без RTOS. ADC та MPU-6050 опитуються з номінальним періодом 20 мс, телеметрія передається раз на секунду. Для вимірювання часових характеристик використовується TIM3 із кроком 1 мкс. Службові GPIO-маркери PA6 та PA7 дозволяють перевіряти періодичність IMU і затримку реакції логічним аналізатором.

## Збірка та запуск

Для компіляції потрібні **Docker** та **make**. Команди виконуються з кореня репозиторію:

```bash
make build
```

Збірка використовує ARM GCC у Docker-контейнері. Результати зберігаються у `firmware/build/`: `firmware.elf`, `firmware.hex` та `firmware.bin`. Для очищення використовується `make clean`.

**Запуск у Wokwi:**

1. Відкрити корінь проєкту у VS Code зі встановленим розширенням **Wokwi Simulator**.
2. Натиснути `F1` та вибрати `Wokwi: Start Simulator`. Шлях до ELF задано у `wokwi.toml`.
3. У UART-терміналі перевірити `[BUILD]`, `[SELF-TEST]`, `System Init OK` та появу `[TELEMETRY]`.

Для демонстрації тривог можна змінювати прискорення MPU-6050, положення `temp1` і стан кнопки `door1`.

Доступні команди `status`, `maint`, `active`, `clear`, `probe`, `sim_nack`, а також вимірювальні `build`, `perf`, `stats`, `stats reset`, `mem`, `load 256- 4096` та `uart stats`.

## Тести та вимірювання

Хостові тести запускаються без симулятора:

```bash
make -C tests all
```

Команда перевіряє залежності шарів, запускає модульні тести, перевірки UART-навантаження й аналізатора журналів та формує звіт покриття `gcov`. Збірка і тести також перевіряються через **GitHub Actions**.

Для ЛР3 підготовлено три основні сценарії: `S1` (простій), `S2` (номінальне навантаження) та `S3` (максимальне навантаження). Додатково реалізовано перевірки затримки реакції дверцят, приймання UART-команд, відмови I²C, тривалої роботи та поведінки під час запуску.

Результати вимірювань зберігаються у `docs/metrics/lab3/`, а записи логічного аналізатора у `docs/captures/lab3/`. Детальний аналіз сценаріїв, обмежень і часових характеристик наведено у звіті ЛР3.

## Відтворення вимірювань

Для автоматизованих сценаріїв S2 і S3 використовуються Python-скрипти з підключенням до UART симулятора через RFC2217 (`localhost:4000`). Потрібна бібліотека `pyserial`.

```bash
python3 tools/run_s2.py --minutes 60 --out docs/metrics/lab3/repeat-S2.log
python3 tools/run_s3.py --minutes 3 --out docs/metrics/lab3/repeat-S3.log
```

У S3 UART-навантаження створюється автоматично, а події удару, перегріву та відкриття дверцят відтворюються вручну. Для обробки журналів використовується `tools/analyze_lab3.py`.
