# Server Rack Health Monitor

Навчальний проєкт студента Лазінька Романа, група ІО-36, з курсу «Системне програмування вбудованих систем».

**Ідея:** система моніторингу фізичного стану серверної стійки. Вона відстежує удари та вібрації корпусу, підвищення температури й відкриття дверцят, а результати виводить через UART.

У **ЛР2** реалізовано спільну роботу датчиків, стартову самоперевірку, режими `ACTIVE` та `MAINTENANCE`, запис і аналіз цифрових сигналів, хостові тести й автоматичну збірку. Проєкт працює на **STM32C031C6** зі **STM32 HAL**.

## Компоненти та робота системи

- **MPU-6050** — акселерометр через I²C1 (адреса `0x68`, PA9/PA10, 100 кГц); використовується для визначення ударів.
- **LM35** — аналоговий датчик температури через ADC1_IN0 (PA0). У Wokwi його вихід емулюється потенціометром `temp1`; поріг тривоги **45°C**.
- **Кінцевий вимикач дверцят** — цифровий вхід PA1 із програмним debounce **50 мс**.

У режимі `ACTIVE` система повідомляє про `SHOCK DETECTED`, `HIGH TEMPERATURE` та `DOOR OPENED`. У режимі `MAINTENANCE` опитування й телеметрія продовжуються, але нові звичайні тривоги не формуються. Повторні тривоги від одного джерела обмежені інтервалом **5 с**.

## Збірка

Потрібні встановлені **Docker** та **make**. Команди виконуються з кореня репозиторію:

```bash
make build
```

Команда збирає Docker-образ на базі `ubuntu:22.04` та компілює прошивку ARM GCC. Результат: `firmware/build/firmware.elf`, `firmware.hex` і `firmware.bin`. Для очищення результатів використовуйте `make clean`.

## Запуск у Wokwi

1. Відкрийте корінь проєкту у VS Code зі встановленим розширенням **Wokwi Simulator**.
2. Після цього натисніть `F1` → `Wokwi: Start Simulator`. Файл `wokwi.toml` уже містить шлях до ELF.
3. У UART-терміналі перевірте `[SELF-TEST]` для трьох входів, повідомлення `System Init OK` і щосекундну телеметрію.

Для демонстрації тривог змінюйте прискорення MPU-6050, положення потенціометра `temp1` і стан кнопки `door1`. Через UART доступні команди `status`, `maint`, `active`, `clear`, `probe` та `sim_nack` (контрольований NACK на I²C-адресі `0x69`).

## Тести та перевірка інтерфейсів

Хостові тести запускаються без плати й симулятора:

```bash
make -C tests all
```

Команда перевіряє залежності модулів `App` і `Devices`, запускає тести з підмінною I²C-шиною та формує звіт `gcov`. Прошивка й тести також перевіряються в **GitHub Actions**.

## Аналіз сигналів у PulseView

Для перевірки цифрових інтерфейсів використовуються записи логічного аналізатора Wokwi.

Для перегляду відкрийте потрібний VCD-файл у **PulseView** через `File → Open`, встановивши під час імпорту `Downsampling factor = 100`. Далі налаштуйте декодери та канали:

- **I²C:** D0 — SCL, D1 — SDA; декодування адрес, даних та ACK/NACK.
- **UART:** D2 — TX, швидкість 115200 бод, формат 8N1.
- **GPIO та ADC:** D3 — стан вимикача дверцят, D4 — службовий маркер процедури ADC.

Часові параметри можна вимірювати курсорами PulseView.
